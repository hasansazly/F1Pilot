# F1Pilot product requirements

## Scope

Build the narrow CPT/OPT preparation loop before future modules: receive evidence → extract proposed facts → preserve provenance → student reviews → deterministic timeline → proactive cards → prepared draft → student decision → recorded result. This is a working local pilot, not a legal service.

## Permanent invariants

- No eligibility, employment-authorization, admission, compliance or approval determinations.
- Important extracted facts require explicit confirmation or correction. Proposed evidence never silently updates a verified timeline.
- Critical date arithmetic belongs to deterministic versioned rules, never a language model.
- Show consequential source references, input evidence, rule version, uncertainty and effective-period limitations.
- Preserve original evidence and prior values until the user explicitly deletes the source.
- External consequential actions require specific approval. Local approval and real external execution are different states.
- Tenant isolation and server-side authorization are required for every private read/write/export.
- Data is private by default. Export, consent history and permanent local deletion remain available.
- Demo records are fictional and clearly identified.

## Acceptance journey

A student can create an account, enter a profile, upload or select a sample I-20, inspect exact transcript page/line citations, confirm fields, receive a timeline and institution-specific fictional preparation requirement, review proactive evidence, prepare an editable DSO email, approve/cancel and inspect the recorded result. Refresh preserves data. Cross-account object IDs cannot reveal or mutate evidence.

## Interface

Today, Timeline, Documents, Inbox, Requirements, Ask F1Pilot, Evidence Map, Employment, Travel, Activity, Data and Privacy, Settings. Original cinematic black/graphite design with subdued violet, blue, amber and rose accents, readable typography, keyboard controls, native modal focus management, mobile navigation and reduced-motion support.

## Deferred modules

Full employment history and STEM reporting, travel admissibility workflows, tax, insurance, finance, marketplace, institutional integrations, rule monitoring and autonomous external tools are outside this narrow build. Do not imply these exist.
